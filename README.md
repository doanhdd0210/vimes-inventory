# VIMES Inventory — Flutter base

Base project for the VIMES inventory dev test (form **Phiếu nhập kho – Mẫu 01‑VT**,
Thông tư 200/2014/TT‑BTC). This `main` branch is the reusable skeleton only;
the test feature is built on the `vimes-dev` branch.

Stack: **Clean Architecture** + **MVVM** (presentation) + **BLoC** + **go_router**
+ **get_it** + **Firebase (Cloud Firestore)**.

## Architecture

```
lib/
├── bootstrap.dart              # shared composition root (Flutter binding, flavor,
│                               #   Firebase, DI, error zone, runApp)
├── app.dart                    # VimesApp — MaterialApp.router + ThemeCubit
├── main.dart / main_dev.dart / main_staging.dart / main_prod.dart   # flavor entry points
├── firebase_options.dart       # generated by `flutterfire configure` (placeholder for now)
│
├── core/                       # cross-feature building blocks
│   ├── constants/              # AppConstants, AssetPaths, FirestoreCollections
│   ├── di/                     # injection_container.dart — get_it service locator (`sl`)
│   ├── error/                  # Exception (data) ↔ Failure (domain) hierarchy
│   ├── extensions/             # context / string / date / num / iterable ext (+ barrel)
│   ├── firebase/               # FirebaseBootstrap.ensureInitialized()
│   ├── flavors/                # Flavor enum + FlavorConfig (per-env values)
│   ├── helpers/                # Validators, AppLogger, Debouncer
│   ├── router/                 # AppRoute enum + AppRouter (GoRouter)
│   ├── storage/                # LocalStorage (shared_preferences) + SecureStorage
│   ├── theme/                  # colors / text styles / spacing / radius / durations
│   │                           #   / styles / AppTheme / ThemeCubit
│   └── usecase/                # UseCase<T,P>, StreamUseCase<T,P>, NoParams
│
└── features/
    └── <feature>/
        ├── data/
        │   ├── datasources/    # remote (Firestore) + local (in-memory) impls
        │   ├── models/         # *Model extends Entity, (de)serialisation
        │   └── repositories/   # *RepositoryImpl — maps Exception → Failure
        ├── domain/
        │   ├── entities/       # pure business objects (Equatable)
        │   ├── repositories/   # abstract contracts
        │   └── usecases/       # one class per action
        └── presentation/       # MVVM
            ├── viewmodel/      # *Bloc (+ event / state) — the ViewModel
            ├── view/           # *Page widgets — the View (state in, events out)
            └── widgets/        # dumb, reusable widgets
```

**Dependency rule:** `presentation → domain ← data`. `domain` imports nothing
from `data`/`presentation`/Flutter. `core` is depended on by everything and
depends on nothing feature-specific.

**MVVM mapping:** the BLoC *is* the ViewModel — it exposes an immutable state,
receives events, and orchestrates use cases. The View never touches a
repository/use case directly; it renders `state` and dispatches events.

`features/sample/` is a complete reference slice (list + add). Delete it or copy
its shape when building a real feature.

## Running

```bash
flutter pub get

# default entry point == dev flavor
flutter run

# explicit flavors (Android product flavors are wired; iOS schemes are a TODO)
flutter run --flavor dev     -t lib/main_dev.dart
flutter run --flavor staging -t lib/main_staging.dart
flutter run --flavor prod    -t lib/main_prod.dart

# run fully offline (in-memory datasources, no Firebase needed)
flutter run --dart-define=USE_FIREBASE=false
```

## Firebase setup (one-time)

**Firebase is temporarily switched off in this base.**
`FlavorConfig.firebaseTemporarilyDisabled = true` forces every flavor onto the
in-memory datasources, so `Firebase.initializeApp` is never called and
`lib/firebase_options.dart` stays a harmless placeholder. The Firestore
datasource / repository / DI wiring is all in place — only the flag is off.

To turn Firebase on:

1. Generate the options (see below).
2. Set `firebaseTemporarilyDisabled = false` in
   `lib/core/flavors/flavor_config.dart` (dev/staging/prod then follow their
   per-flavor `useFirebase` default of `true`).

```bash
# the CLI token in this environment is expired — re-auth first:
firebase login --reauth

dart pub global activate flutterfire_cli
flutterfire configure \
  --project=<your-firebase-project-id> \
  --out=lib/firebase_options.dart \
  --platforms=android,ios
```

`flutterfire configure` also drops `android/app/google-services.json` and
`ios/Runner/GoogleService-Info.plist`. Decide per repo whether those are
committed (see `.gitignore`).

For flavor-specific Firebase projects, run `flutterfire configure` once per
flavor with `--android-package-name` / `--ios-bundle-id` matching the suffixed
ids (`com.doanhdd.vimes_inventory.dev`, `.staging`, and the base id for prod).
